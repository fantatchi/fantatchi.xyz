Claude Code は、使い込むほど「自分専用」に育っていく AI だ。いつも守ってほしいことを書いておく指示書（CLAUDE.md）、会話をまたいで Claude が自分で残す長期メモ（Memory）、よく頼む作業の手順書（スキル）。こうしたものを足していくと、毎回説明しなくても話が通じるようになる。

この記事では日本語の呼び名で書くが、カッコ内が Claude Code での正式な名前だ。自分の環境で試すときは、こちらの名前で調べると公式ドキュメントにたどり着ける。

ただ、足すのは簡単でも、捨てるのは後回しになりやすい。半年も使うと、もう使っていない手順や、とっくに変えたルールが残る。Claude は書いてあることを律儀に守るので、古い指示がそのまま残っていると、今のやり方と違う動きをする。人間の職場でいえば、改訂されないまま残った業務マニュアルに近い。

そこで私は、週に 1 回、この「育てたもの」を棚卸しする手順を作って回している。この記事はその紹介だ。

## 前提: 私の環境はかなり特殊

先に断っておくと、私の使い方は一般的ではない。

- Windows の中で Linux を動かし（WSL という仕組み）、その上で Claude Code を使っている
- 職場と自宅など複数の PC で使い、指示書や手順書は GitHub で管理して全 PC に同じものを配っている
- メモや作業記録はノートアプリの Obsidian に置き、PC とスマホで同期している
- Claude Code と並行して、OpenAI の Codex も使っている

なので、ここに書く手順をそのまま真似できる人は少ないと思う。それでも「AI に育てたものは定期的に見直さないと古くなる」という部分は、環境に関係なく当てはまるはずだ。環境の組み方そのものも、反響があれば別の記事で書こうと思っている。

## 週 1 回、AI のほうから声をかけてもらう

棚卸しで最初に困ったのは、やるのを忘れることだった。そこで、前回の棚卸しから 7 日以上経っていたら、Claude に話しかけたタイミングで「そろそろ点検の時期です」とアラートが出るようにした。これは hook（決まったタイミングで自動で処理を走らせる機能）で作っている。最後に点検した日時は Obsidian に記録してあるので、どの PC で点検しても、全 PC のアラートが止まる。

## 棚卸しの 4 つの中身

点検は 4 つに分かれている。1 つ目だけは私の確認なしで Claude に済ませてもらい、残り 3 つは Claude が出した提案をまとめて見て、どれを採用するか私が選ぶ。

### 1. 「なぜそう決めたか」のメモを整理する（確認なしで実行）

私は Claude と作業するとき、「この件はこう決めた、理由はこう」というメモを残させている。後から同じ議論を繰り返さないためだ。ただ、これは放っておくと増える一方なので、点検のたびに Claude に 1 件ずつ仕分けてもらう。

- どの作業でも役に立つ教訓 → Claude が毎回読む長期メモへ移す
- もう別の場所に書いてある、または期限切れ → 消す
- 「こうなったら見直す」という条件付きで、まだ生きている → 残す

以前は、この仕分け内容を毎回私が確認していた。でも実際には全件そのまま承認しかしていなかったので、確認なしで実行してもらう形にした。その代わり、消すメモは元の文面のまま作業記録に移してから消す。間違って消しても、そこから戻せる。

### 2. 指示書を見直す

Claude Code には、毎回の会話の最初に読み込まれる指示書（CLAUDE.md というファイル）がある。見直しの基準は「Claude が自分では知りようのないことだけを残す」。

たとえば「丁寧なコードを書いて」のような一般論は、Claude はもう知っている。書いても指示書が長くなるだけだ。逆に、私の好みや職場の事情、過去にハマった環境のクセは、書かないと伝わらない。あわせて、指示書の中で名前を出しているファイルが今も実在するかも確かめてもらう。

### 3. Claude の長期メモ（Memory）を見直す

Claude は会話の中で「これは覚えておこう」と判断したことを、自分で長期メモに書き足していく（Memory の中でも、auto memory と呼ばれる機能）。便利だけれど、気付くと古くなっている。そこで次の点を見てもらう。

- メモの中で名前を出しているファイルや仕組みが、今もあるか
- 指示書と同じことを二重に書いていないか
- 「まだ分からない」「とりあえず」と書いたまま、3 か月以上放置していないか

最後の項目は、Claude に正しいかどうかを判定させず、「これ、今も合ってますか？」という質問の形で私に出してもらう。答えを知っているのは私のほうだからだ。

### 4. 使っていない手順書を探す

Claude Code には、よく頼む作業を手順書として登録しておける（スキルと呼ばれる）。私は 20 個以上作っているが、全部使っているわけではない。そこで、どの手順書を何回使ったかを集計してもらっている。

これを始めたきっかけは、作ったのに一度も使われない手順書があったことだ。「こういう場面では Claude が自分の判断で使ってくれる」つもりで入れたものが、1 か月近く経っても一度も使われていなかった。手順書は、入れたからといって使われるとは限らない。

ただし、使われていないからすぐ消す、とはしない。年に数回しか出番のない作業もあるので、集計が 90 日分たまるまでは参考として眺めるだけにしている。

## まずは月 1 回、聞くだけでいい

ここまで書いた仕組みを全部そろえる必要はない。Claude Code に「CLAUDE.md を読んで、古くなっていそうなところを挙げて」と頼むだけでも、棚卸しは始められる。Memory も同じで、「今の Memory の中で、もう合っていなさそうなものはある？」と聞けば候補を出してくれる。

ただ、出てきた候補を消すかどうかは自分で決める。その指示がまだ必要かどうかを知っているのは、Claude ではなく使っている本人のほうだ。

私がこれを週 1 回の仕組みにしたのは、手で聞くのをすぐ忘れたからだ。忘れずに続けられるなら、月 1 回、聞くだけで十分だと思う。

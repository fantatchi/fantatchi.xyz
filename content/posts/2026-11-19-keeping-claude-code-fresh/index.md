Claude Code は、使い込むほど「自分専用」に育っていく AI だ。いつも守ってほしいことを書いておく CLAUDE.md、会話をまたいで Claude が自分で残す自動メモリ、よく頼む作業の手順を登録しておくスキル。こうしたものを足していくと、毎回説明しなくても話が通じるようになる。

ただ、足すのは簡単でも、捨てるのは後回しになりやすい。半年も使うと、もう使っていない手順や、とっくに変えたルールが残る。Claude は書いてあることを律儀に守るので、古い指示がそのまま残っていると、今のやり方と違う動きをする。人間の職場でいえば、改訂されないまま残った業務マニュアルに近い。

そこで私は、週に 1 回、この「育てたもの」を棚卸しする手順を作って回している。この記事はその紹介だ。

## 前提: 私の環境はかなり特殊

先に断っておくと、私の使い方は一般的ではない。

- Windows の中で Linux を動かし（WSL という仕組み）、その上で Claude Code を使っている
- 職場と自宅など複数の PC で使い、CLAUDE.md やスキルは GitHub で管理して全 PC に同じものを配っている
- メモや作業記録はノートアプリの Obsidian に置き、PC とスマホで同期している
- Claude Code と並行して、OpenAI の Codex も使っている

なので、ここに書く手順をそのまま真似できる人は少ないと思う。それでも「AI に育てたものは定期的に見直さないと古くなる」という部分は、環境に関係なく当てはまるはずだ。環境の組み方そのものも、反響があれば別の記事で書こうと思っている。

## 週 1 回、AI のほうから声をかけてもらう

棚卸しで最初に困ったのは、やるのを忘れることだった。そこで、前回の棚卸しから 7 日以上経っていたら、Claude に話しかけたタイミングで「そろそろ点検の時期です」とアラートが出るようにした。これはフック（決まったタイミングで自動で処理を走らせる機能）で作っている。最後に点検した日時は Obsidian に記録してあるので、どの PC で点検しても、全 PC のアラートが止まる。

## 棚卸しの 5 つの中身

点検は 5 つに分かれている。1 つ目だけは私の確認なしで Claude に済ませてもらい、残り 4 つは Claude が出した提案をまとめて見て、どれを採用するか私が選ぶ。

### 1. 「なぜそう決めたか」のメモを整理する（確認なしで実行）

私は Claude と作業するとき、「この件はこう決めた、理由はこう」というメモを残させている。後から同じ議論を繰り返さないためだ。ただ、これは放っておくと増える一方なので、点検のたびに Claude に 1 件ずつ仕分けてもらう。

- どの作業でも役に立つ教訓 → Claude が毎回読む自動メモリへ移す
- もう別の場所に書いてある、または期限切れ → 消す
- 「こうなったら見直す」という条件付きで、まだ生きている → 残す

以前は、この仕分け内容を毎回私が確認していた。でも実際には全件そのまま承認しかしていなかったので、確認なしで実行してもらう形にした。その代わり、消すメモは元の文面のまま作業記録に移してから消す。間違って消しても、そこから戻せる。

### 2. CLAUDE.md を見直す

CLAUDE.md は、毎回の会話の最初に読み込まれる。見直しの基準は「Claude が自分では知りようのないことだけを残す」。

たとえば「丁寧なコードを書いて」のような一般論は、Claude はもう知っている。書いても CLAUDE.md が長くなるだけだ。逆に、私の好みや職場の事情、過去にハマった環境のクセは、書かないと伝わらない。あわせて、CLAUDE.md の中で名前を出しているファイルが今も実在するかも確かめてもらう。

### 3. 自動メモリを見直す

Claude は会話の中で「これは覚えておこう」と判断したことを、自動メモリに書き足していく。便利だけれど、気付くと古くなっている。そこで次の点を見てもらう。

- メモの中で名前を出しているファイルや仕組みが、今もあるか
- CLAUDE.md と同じことを二重に書いていないか
- 「まだ分からない」「とりあえず」と書いたまま、3 か月以上放置していないか

最後の項目は、Claude に正しいかどうかを判定させず、「これ、今も合ってますか？」という質問の形で私に出してもらう。答えを知っているのは私のほうだからだ。

### 4. 使っていないスキルを探す

Claude Code には、よく頼む作業の手順をスキルとして登録しておける。私は 20 個以上作っているが、全部使っているわけではない。そこで、どのスキルを何回使ったかを集計してもらっている。

これを始めたきっかけは、作ったのに一度も使われないスキルがあったことだ。「こういう場面では Claude が自分の判断で使ってくれる」つもりで入れたものが、1 か月近く経っても一度も使われていなかった。スキルは、入れたからといって使われるとは限らない。

ただし、使われていないからすぐ消す、とはしない。年に数回しか出番のない作業もあるので、集計が 90 日分たまるまでは参考として眺めるだけにしている。

### 5. 許可の確認が多いコマンドを洗い出す

（この項目は、記事を公開した後に足した）

Claude Code は、許可の一覧（allowlist）に入っていないコマンドを実行する前に、私に確認を求める。読むだけのコマンドで何度も確認が出ると、作業がそのたびに止まる。

そこで、Claude Code に組み込みの `/fewer-permission-prompts` を使い、過去の会話で確認が多かったコマンドを洗い出してもらう。許可の一覧に足すかどうかは私が選び、足す先も私が決める。全 PC で使うものは全 PC 共通の設定に、特定の PC でしか使わないものはその PC だけの設定に置く。

## まずは月 1 回、聞くだけでいい

ここまで書いた仕組みを全部そろえる必要はない。Claude Code に「CLAUDE.md を読んで、古くなっていそうなところを挙げて」と頼むだけでも、棚卸しは始められる。自動メモリも同じで、「今の自動メモリの中で、もう合っていなさそうなものはある？」と聞けば候補を出してくれる。

ただ、出てきた候補を消すかどうかは自分で決める。その指示がまだ必要かどうかを知っているのは、Claude ではなく使っている本人のほうだ。

私がこれを週 1 回の仕組みにしたのは、手で聞くのをすぐ忘れたからだ。忘れずに続けられるなら、月 1 回、聞くだけで十分だと思う。

Claude Code は、そのままでも使える。ただ、使い込むうちに、CLAUDE.md を書き、スキルを登録し、フックを足していくことになる。こうして本体の周りに足したもの一式を、この記事ではハーネスと呼ぶ。

「[私の私による私のための Claude Code](/posts/2026-11-19-my-own-claude-code/)」では、部品ごとに「何に困ってこうしたか」を書いた。この記事では理由には深入りせず、構造だけを整理する。どこに何を置いているか、それがいつ Claude に読み込まれるか、誰が書くのかの 3 点だ。週 1 回の点検で何を見ているかは、この構造を知っていると分かりやすくなるので、次の記事で書く。

## 前提: 私の環境

- 職場と自宅など、複数の PC で使っている。主に Windows の中で Linux を動かす WSL の上で使い、Windows で直接動かす PC もある
- 設定は dotfiles 管理ツールの chezmoi で GitHub に置き、全 PC に配っている
- メモや作業記録はノートアプリの Obsidian に置き、PC とスマホで同期している
- Claude Code と並行して、OpenAI の Codex も使っている

もう 1 つ断っておくと、私は Claude Code の公式ドキュメントをあまり追えていない。この記事の構造は、使いながら困ったところを直して積み上げたもので、今の推奨の使い方からは外れているところがあるかもしれない。

その代わり、設定やスキルを直すときは、基本的に Claude Code 自身に頼んでいる。そのとき、最新の公式ドキュメントも Claude Code に調べてもらっている。

## 部品の一覧

ハーネスを構成する部品は次のとおりだ。

| 部品 | 中身 | 書くのは誰か |
|---|---|---|
| CLAUDE.md | 全プロジェクト共通の約束事、約 120 行。プロジェクトごとの CLAUDE.md もある | 私 |
| 自動メモリ | 会話をまたいで覚えておくこと。プロジェクトごとに 1 か所 | Claude（自分の判断で書く） |
| スキル | よく頼む作業の手順を登録しておける仕組み。自作を中心に 20 個以上 | 私（Claude に書かせて私が直す） |
| フック | 起動時・入力時・コミット直後などに走る小さなスクリプト | 私 |
| プラグイン | 他の人が作ったスキルやフックの詰め合わせ。公式のものを中心に十数個 | 他の人 |
| 作業状態のメモ | プロジェクトごとの進み具合と、なぜそう決めたかの記録 | Claude（スキルの手順に沿って） |
| 作業ログ・台帳 | Obsidian に置く、後から振り返るための記録 | Claude とスクリプト |

## いつ読み込まれるか

構造を考えるうえで一番大事なのは、それぞれがいつ Claude に読み込まれるかだ。読み込まれるたびに、Claude が一度に扱える文章量（コンテキスト）を使う。毎回読み込まれるものほど、短く保つ必要がある。

| タイミング | 読み込まれるもの |
|---|---|
| 会話の開始時に毎回 | CLAUDE.md の全文、自動メモリの索引（MEMORY.md）、すべてのスキルの説明文（1〜数行ずつ） |
| 起動時（フックが差し込む） | 作業状態のメモの要点、受け箱に投げ込んだ「あとでやる」 |
| 入力のたびに（フックが判定する） | 保存の催促、週 1 回の点検の通知、配布元との差分の通知。条件を満たしたときだけ出る |
| コミットの直後 | 作業状態を保存するよう促す |
| 使うときだけ | スキルの本文、自動メモリの各ファイル、作業ログ |

ここで押さえておきたいのは、スキルは本文ではなく説明文が毎回読み込まれることだ。Claude は説明文を見て、どのスキルを使うかを自分で判断する。つまり、使っていないスキルも、置いてあるだけで毎回の会話に説明文の分の負担をかけている。私が手でしか呼ばないスキルは「手動専用」にしてあり、そうすると説明文も読み込まれなくなる。

自動メモリも同じ作りで、毎回読み込まれるのは 1 件 1 行の索引だけだ。中身は、Claude が関係があると判断したときに開く。

## どこに置いているか

置き場所は 4 つに分かれる。

### 全 PC 共通（chezmoi で配る）

CLAUDE.md、スキル、フックのスクリプト、Claude Code の共通設定（settings.json）は、chezmoi で GitHub に置いて全 PC に配っている。Claude Code の設定ファイルのうち、使うモデルの指定や、特定の PC にしかないフォルダへの許可は、PC ごとの設定（settings.local.json）に書いて配らない。

フックは、Linux 用のシェルスクリプトと Windows 用の PowerShell スクリプトを両方用意し、間に Node.js の小さなラッパーを挟んで OS ごとに呼び分けている。これで設定ファイルを全 PC で共通にできる。

chezmoi は配布元のファイルを PC へ写す道具なので、PC 側で直接ファイルを直すと、配布元とずれる。入力のたびに走るフックが、このずれを見つけて知らせる。

### プロジェクトごと（リポジトリの中）

各リポジトリの `.claude/` フォルダに、作業状態のメモ・やることリスト・引き継ぎメモの 3 つを置いている。git の管理からは外している。

作業状態のメモには、主に 2 つの欄がある。

- 進行中の作業: 今何をしていて、どこまで進んだか。完了してから 14 日経ったものは、保存のたびに自動で消す
- 判断メモ: 「この件はこう決めた、理由はこう」。こちらは日付では消さない。後から同じ議論を繰り返さないための記録なので、古くても効いているものがあるからだ

判断メモは消さないぶん増えていく。15 件または 6KB を超えると、保存のときに警告を出すようにしている。どれを残してどれを外すかは、週 1 回の点検で仕分ける。

### Claude Code が管理する場所

自動メモリは、Claude Code がプロジェクトごとに用意するフォルダに置かれる。このフォルダは chezmoi の管理外で、PC ごとにばらばらになる。書くのも Claude なので、私が中身を把握しているとは限らない。

### Obsidian

作業ログ、日報、記事の下書きは Obsidian に置いている。作業状態のメモが「次の作業のための短いメモ」なのに対し、作業ログは「後から振り返るための記録」で、消さない。作業状態のメモが膨らんだら、詳細を作業ログに逃がしてリンクだけ残す。

PC をまたいで共有したい小さな状態もここに置いている。たとえば、最後に点検した日時と、スキルの利用回数の台帳だ。Obsidian は全 PC で同期しているので、どの PC で点検しても、全 PC の点検通知が止まる。

## Codex 側

Codex にも同じ形のハーネスを置いている。AGENTS.md は CLAUDE.md をほぼ写したもので、スキルも Claude 側の写しを置いている。Codex 専用のスキルは作らない方針で、正本は Claude 側だ。Claude 側でスキルを直したら Codex 側も直し、消したら Codex 側も消す。

作業状態のメモと引き継ぎメモは、Claude と Codex で同じファイルを読み書きする。どちらも同じ作業フォルダを見るので、Claude で詰まったら Codex に渡し、Codex で詰まったら Claude に戻す、という往復ができる。

## 増えるもの、古くなるもの

部品を並べると、ハーネスの中には放っておくと増えるものと、古くなるものがあることが分かる。

- 増えるもの: 判断メモ、自動メモリ、スキル
- 古くなるもの: CLAUDE.md の中のルール、自動メモリの中身、スキルが前提にしているファイル名
- ずれるもの: 配布元と PC、Claude 側と Codex 側

特に、Claude が自分で書く自動メモリと判断メモは、私が書いていないぶん中身を把握しにくい。毎回読み込まれる CLAUDE.md やスキルの説明文は、古いまま残ると毎回の会話に影響する。

## 育てるときに決めること

ここまでの整理から、Claude Code に何かを足すときに決めておくとよいことを 3 つ挙げる。私の構造をそのまま真似る必要はないが、この 3 つは環境が違っても決めることになるはずだ。

1. **毎回読み込まれるか、使うときだけか**: 毎回読み込まれるものは、短く保つ。CLAUDE.md に長い手順を書くより、スキルに分けて説明文だけが毎回読まれる形にしたほうが軽い。手でしか呼ばないスキルは手動専用にする
2. **書くのは自分か、Claude か**: 自分が書くものは、自分が中身を知っている。Claude が書くもの（自動メモリや、Claude に書かせる記録）は、知らないうちに増え、推測が事実のように残ることがある。こちらは定期的に見直す対象にする
3. **正本はどこか**: 複数の PC や、Claude Code 以外のツールでも使うなら、どれを正本にして、どう写すかを決める。決めずに両方で直すと、必ずずれる

この 3 つを決めておくと、何がいつ古くなるか、どこを見直せばよいかも見えてくる。私はそれを週に 1 回まとめて点検している。その中身は次の記事で書く。
